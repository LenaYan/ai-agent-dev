# 字面匹配 vs 向量检索：一次受控对比

> 时间：2026-07-27 首轮；**2026-07-28 空样本从 3 条补到 11 条后重扫两条前沿**。
> §2/§3 的前沿与工作点、§4 的字面列是重扫后的值；
> **§4 的向量列与 §5 的多数代价数字仍来自 2026-07-27**，各处已就地标注口径 ——
> 本轮不装可选依赖（要保住"零模型依赖"这条性质的干净验证，见 §5.2）。
> 模型：BAAI/bge-m3（本地开放权重，dense 单路）。
> 设计与判据见 `docs/superpowers/specs/2026-07-27-rag-vs-literal-design.md`；
> 被检验的决定是 `memory/decisions.md` ADR-0006。
>
> **结论先说：向量没有赢。** 同工作点（空样本正确率 = 100%）上
> **字面 79%（阈值 0.25）、向量 53%（阈值 0.75）**，差 26 个百分点。
> 这个实验最想看的两条（"具体数字被换掉字面就废"）向量一条也没救回来。
>
> **但本轮真正的收获不是这两个数字，而是 §6.0**：上一轮那个"同工作点 =
> 空样本正确率 100%"的判据，**它的分母只有 3**。纪律是对的，纪律锚定的
> 那个指标当时太脆。补到 11 条之后每一个基线数字都变了。

## 1. 实验怎么设计的（只动一个变量）

被替换的只有 `_relevance(Q, T)` 的内部实现：从"双向字符二元组覆盖率取大者"
换成"余弦相似度"。除此之外一行不动 ——

- 聚合结构不动：误概念仍是 statement 为主、probe / correction_hint 为次
  （`SECONDARY_WEIGHT = 0.5`）；知识点仍是 name 为主、description 为次
  （`DESCRIPTION_WEIGHT = 0.5`）；任一字段过门槛即入选，加权分只用于排序。
- 语料不动：同一份 `data/generated/graph.json`（64 节点 / 75 条误概念 /
  353 条可检索文本）。**[2026-07-29 补注：本文全部数字绑定这张 64 节点图，
  换图不复现 —— 07-28 的 66 节点图上字面基线是 59%、07-29 的 78 节点图上是 65%
  （同一工作点）。结论「向量没有赢」不受影响，因为那是在这张固定的图上
  只换打分器的单变量对比；受影响的只是拿 79% 当"当前检索水平"去引用。]**
- 评测不动：同一份 **30 条** ground truth（19 条计召回 + **11 条"应当召回不到"**）。
  两条路线看到的是同一份，重扫时两条一起重扫 —— 见 §1.1。
- 阈值**不是**挑出来的：两条路线各自扫完 0.05–0.95 的完整前沿，
  在**空样本正确率 = 100% 这个相同工作点**上读 recall@3。

分层靠 `serve/embedding.py` 的 `Embedder` 协议：那是整个 `serve/` 里唯一
import 模型库的地方，领域层只认协议。代价是可选依赖（`uv sync --extra embed`），
收益是**默认 `uv sync` 后 396 个测试一个不少地全绿、零模型依赖** ——
这条性质在本轮结束时重新验证过（见 §5 末）。

复现命令：

```bash
uv sync --extra embed
uv run python scripts/eval_diagnosis.py --scorer literal --threshold-sweep
uv run python scripts/eval_diagnosis.py --scorer vector  --threshold-sweep
# 逐条明细停在各自的同工作点上（--min-relevance 就是为这件事加的）：
uv run python scripts/eval_diagnosis.py --scorer literal --min-relevance 0.25
uv run python scripts/eval_diagnosis.py --scorer vector  --min-relevance 0.75
```

## 1.1 空样本从 3 条补到 11 条：补法、动机、以及刻意排除的两类

**动机**：2026-07-28 先试着把生产阈值 `LiteralScorer.min_relevance` 从 0.2 改到 0.15
（依据是上一轮 §3 那个"让出 5 个百分点"的发现），因为一条单测变红而改了回来。
那次实测暴露的**不是阈值问题，是判据问题**：评测在 0.15 上报空样本正确率
100%，而单测里"孩子不爱吃青菜"（相关度 0.1667）照样被凑出候选。
两个结果不矛盾 —— **ground truth 里只有 3 条空样本，覆盖不到这个模式**。
一个分母为 3 的百分比撑不起阈值决策，更撑不起整个实验的公平性判据（§6.0）。

**补法（这是本轮结果可信的前提，所以写在这里而不是脚注）：**

1. **先定分类，按分类把 8 条样本写死，写完才第一次跑分数。**
   顺序很重要 —— 反过来（跑一遍看谁漏了再补样本）等于拿被测系统的输出
   去设计测它的集合，得到的 100% 什么也不说明。
2. 分类与条数（新增 8 条 = 5 + 2 + 1，加上已有的 3 条共 11 条）：
   - **其他领域 5 条** —— 本图只覆盖课标的"数与代数"，这几条落在别的领域：
     统计与概率 2（`empty_probability_gambler`、`empty_bar_chart`）、
     图形与几何 2（`empty_protractor`、`empty_solid_vs_plane`）、
     综合与实践 1（`empty_calendar`）。
   - **完全非数学 2 条**：`empty_homework_habit`（写作业拖拉）、
     `empty_test_anxiety`（考试紧张）。
   - **太笼统无从诊断 1 条**：`empty_too_vague`（"就是学不好，说不上来差在哪"）。
3. **刻意不含两类**，理由都是"它们测的不是这道门槛"：
   - **领域内但图没覆盖**（百分数、负数、解方程）：它们旁边都有相邻节点，
     "该不该召回"标签本身有争议，混进来会污染指标而不是提高分辨率。
   - **说的是对的**（家长转述的是一条正确说法）：那测的是"能不能分辨对错"，
     是另一个问题，不该混进"敢不敢返回空"。

新样本已在 `data/diagnosis-eval-groundtruth.json`，`_note` 字段记了同样的说明。
observation 仍一律是家长口吻的改写，不抄 statement 原文（有防抄测试兜着）。

## 2. 完整阈值前沿（两条曲线并排）

整条曲线落盘，不只报一个点 —— 好让"这个方法在别的工作点上什么样"可查。

下表是 **11 条空样本**下的重扫结果（2026-07-28）。空样本正确率一列的分母
是 11；recall@3 一列的分母是 19，**它与空样本条数无关**，所以 recall 列的值
与上一轮相同 —— 变的是每个阈值配的空样本正确率，而工作点由后者决定。

| 0.10 | 89% | 45% | 89% | 0% |
| 0.15 | 89% | 91% | 89% | 0% |
| 0.20 | 84% | **91%**（生产默认值） | 89% | 0% |
| **0.25** | **79%** | **100%** ← 字面同工作点 | 89% | 0% |
| 0.30 | 68% | 100% | 89% | 0% |
| 0.35 | 58% | 100% | 89% | 0% |
| 0.40 | 53% | 100% | 89% | 0% |
| 0.45 | 47% | 100% | 89% | 0% |
| 0.50 | 42% | 100% | 89% | 0% |
| 0.55 | 26% | 100% | 89% | 0% |
| 0.60 | 21% | 100% | 95% | 9% |
| 0.65 | 16% | 100% | 95% | 64% |
| 0.70 | 11% | 100% | 79% | 91% |
| **0.75** | 11% | 100% | **53%** | **100%** ← 向量同工作点 |

| 0.90 | 0% | 100% | 5% | 100% |
| 0.95 | 0% | 100% | 0% | 100% |

**曲线的形状比端点值更有信息量：**

- **字面版的动态范围是 0.05–0.80（宽 0.75）**，recall 沿这段平滑下滑
  95% → 0%。分数把"相关"和"不相关"拉得开。
- **向量版的动态范围只有 0.60–0.95（宽 0.35）**，而且前 11 个阈值
  （0.05–0.55）**完全平坦** —— recall 恒 89%、**空样本正确率恒 0%**。
- **"空样本正确率在 0.55 以下全是 0%"这一条，在 11 条空样本下才真正有分量。**
  上一轮它是 0/3，可以辩解成"三条恰好都难"；现在是 **0/11** —— 十一条
  分属三个互斥的类别（其他领域 / 完全非数学 / 太笼统），**没有一条**能在
  余弦 0.55 以下被判为"不相关"。也就是说 bge-m3 对
  "孩子写作业拖拉，一坐下就要玩橡皮"和一条小学数学误概念，照样给出 0.55
  以上的余弦。上一轮"判别力不够"这个论断当时靠的是间接推理（平坦段 +
  非单调跳变），**现在有了直接得多的证据：它对完全不相关的文本给不出低分。**
- 于是向量版的困境是结构性的：要让 11 条"应当召回不到"的样本真的全部召回
  不到，阈值必须推到 **0.75**；而它真正的召回峰值（95%）在 0.60–0.65，
  那里空样本正确率只有 9%/64%。**"敢返回空"和"召得回"这两个需求在它的
  分数分布上重叠了。**
- **字面版也没能完全躲开这个矛盾，只是躲得远得多**：它的两个需求在 0.25
  才同时满足，代价是 recall 从 89% 降到 79%（补样本前是 0.15 处两者同时
  满足、不花代价 —— 那个"免费"是 3 条空样本给的假象，见 §6.0）。
- **向量前沿还有一处非单调：0.55 → 89%、0.60 → 95%，提高阈值 recall 反而
  上升。** 这不是噪声，是 `limit=5` 截断的副作用：0.55 以下噪声候选大量
  过门槛，把真正命中的候选挤出了前 3/5 名；阈值抬到 0.60 后一批噪声候选
  被筛掉，原本排不进前 5 的真命中才浮上来。换句话说，**在 0.55 这个阈值上，
  真命中经常根本没排在候选集里** —— 这比"平坦段"本身更直接地证明了
  判别力不够（分数没把真命中和噪声排开，而不只是没把它们的分数拉开）。
  这条解读**在新数据下原样成立**：recall 列没变，非单调的位置也没变。
- **变的是空样本那一列的爬升形状**：0% (≤0.55) → 9% → 64% → 91% → 100%。
  它在 0.60–0.75 这 4 个刻度里从 0 冲到 1，**比上一轮 3 条样本时看到的
  0%→33%→67%→100% 细腻得多，也更陡** —— 上一轮那条"曲线"其实只有四个
  可能取值，形状是被分母 3 量化出来的，不是模型的性质。

这不是"语义理解不够"的问题，是**判别力（separability）**的问题。

### 3.1 层层更正：这条"基线"被改了两次，两次都是判据变了而不是模型变了

- **第一层（2026-07-27）**：长期被引用的"字面基线 84%"是生产默认阈值 0.2
  上的读数，**84% 本身没算错，错的是拿它当基线** —— 当时同工作点在 0.15，
  基线应是 89%。
- **第二层（2026-07-28，本轮）**：**89% 也不再是基线。** 补到 11 条空样本
  后，0.15 的空样本正确率是 **91%（10/11）**，够不到 100% 那个工作点；
  同工作点右移到 **0.25**，基线是 **79%**。
- **顺带，上一轮那句"0.15 同时拿到 89% 召回和 100% 空样本正确率"也被证伪了**
  —— 它当时是对的，但只在 3 条空样本的意义上对。**一个论断的寿命不会超过
  它所依赖的那个指标的分辨率。**

现在引用基线请用 **79% @ 0.25**（同工作点口径），或明确写清"84% @ 0.2
（生产默认值）"这种带阈值的读法。**光写一个百分比、不写它站在哪个工作点上，
这条笔记已经栽过两次了。**

### 3.2 生产默认值 0.2 现在有一条已知误招

生产默认值 `LiteralScorer.min_relevance = 0.2` 的空样本正确率
**不再是 100%，是 91%（10/11）**。
漏的那条是 `empty_bar_chart`：

- 观察句："看条形统计图的时候他只会说哪根柱子最高，读不出具体的数量。"
- 误招：「用字母表示关系」的 statement「字母只能代表一个具体的数，不能代表
  变化的量。」
- 相关度 **0.2105**，重叠的是"具体的数"这类通用词 —— **典型的字面误招**，
  和单测里"孩子不爱吃青菜"命中"引导孩子对齐数位"是同一个失败模式，
  只是这次它出现在生产默认值上，而不是在一个被否掉的候选值上。

> **本轮不改任何代码，`LiteralScorer.min_relevance` 保持 0.2。**
> 但要讨论的问题已经换了：**不再是 0.15 vs 0.2，而是 0.2 vs 0.25。**
> **[2026-07-28 已决定：留在 0.2]** —— 这条误招被**接受为已知代价**，
> 不是被忽略。两栏账与重开条件见 `docs/rag-vs-literal-backlog.md`。

## 4. 逐条看未命中样本的变化：字面赢在哪、向量赢在哪

> ⚠️ **本节的两列来自不同的工作点，读之前先看清口径。**
>
> - **字面列是本轮实跑**（`--min-relevance 0.25`，2026-07-28），就是 §3 那个
>   100% 工作点。
> - **向量列是上一轮的数据**（`--min-relevance 0.70`，2026-07-27）。
>   **本轮没有在新工作点 0.75 上取向量的逐条明细** —— 那要重新装 GB 级
>   可选依赖，而本轮的硬约束是保持 `.venv` 干净（零模型依赖，见 §5.2）。
>   所以 **`向量 @0.75` 那一列本文没有，也不去猜**。
> - **一个可用的锚点**：逐条命中与空样本条数无关，所以 `字面 @0.15` 与
>   `向量 @0.70` 这两列在新 ground truth 下依然是它们各自阈值上的真实命中；
>   而这两个阈值的空样本正确率**恰好都是 91%（10/11）** —— 也就是说
>   **旧的那对阈值今天仍然构成一个匹配的工作点，只是匹配在 91% 而不是 100%。**
>   下表因此把三列并排：两列在 91% 工作点上可直接对比，第三列（字面 @0.25）
>   是 100% 工作点上的字面侧。

| 样本 | 字面 @0.25（100% 工作点，本轮实跑） | 字面 @0.15（91% 工作点） | 向量 @0.70（91% 工作点，**上一轮数据**） |
|---|---|---|---|
| `dec_more_digits_bigger` | ✗ 错召"比较万以内数的大小" | ✗ | ✗ |
| `order_of_operations` | ✗ 空手而归 | ✗ | ✗ |
| `frac_unit_compare` | ✓ 分数的意义 | ✓ 分数的意义 | ✗ 错召"认识成正比的量" |
| `place_value_ignored` | **✗ 空手而归** | ✓ 数位的含义 | ✗ 空手而归 |
| `compare_only_first_digit` | **✗ 空手而归** | ✓ | ✓ |
| 其余 14 条 | ✓ | ✓ | ✓ |
| **合计 recall@3** | **79%（15/19）** | 89%（17/19） | 79%（15/19） |

**在 91% 工作点上（两列同口径可比）：向量独赢 0 条，字面独赢 2 条 ——
向量的命中集 ⊊ 字面的命中集，严格包含，不是"各有千秋"。** 这条结论在
新 ground truth 下**原样成立**，因为它只依赖 19 条计分样本的逐条命中。

**在 100% 工作点上（§3 那对，53% vs 79%）无法做同样的逐条断言** —— 向量
@0.75 的命中集本轮没取。已知的只有它命中 10 条、字面命中 15 条。
**"真子集"这个说法请只用在 91% 工作点上，不要外推到 26pp 那个对比上。**

**字面从 0.15 抬到 0.25 掉的两条**（`place_value_ignored`、
`compare_only_first_digit`）都是**从命中变成空手而归**，不是变成误召 ——
门槛抬高时字面版是"宁可不说"，这与它在空样本上冲到 100% 是同一件事的两面。

### 4.1 最该看的一件事：立项理由的那几条，向量一条也没救回来

这个实验的立项理由写在设计文档 §0：字面版剩下的未命中"都指向具体数字被
换掉后字面匹配就废了"，而**那正是向量检索天然该解决的问题**。逐条对照：

- **`order_of_operations`**（"算 20+5×2 的时候他从左往右做" vs 图里的
  `15+3×4`）—— 立项时点名的那一条。**字面 ✗，向量也 ✗（空手而归）。**
  向量在 0.70 上给这对文本的相似度过不了门槛。
- **`dec_more_digits_bigger`**（"小数点后面位数越多这个数就越大" vs 图里的
  "0.3 比 0.03 小"，抽象规则 vs 具体数字）—— **字面 ✗，向量也 ✗**，
  而且两者错召的是同一个节点（`t_0c99418298` 比较万以内数的大小）。
- **`compare_only_first_digit`**（同义换词）—— 曾被列为字面版的三条未命中
  之一。上一轮的结论是"**它根本不需要向量**：字面版把阈值从 0.2 挪到 0.15
  就召回了"。**这条结论本轮要打个折**：0.15 确实召回它，但 0.15 现在够不到
  100% 工作点；**在真正的同工作点 0.25 上它又变回未命中**。
  准确的说法是：**它是一个阈值敏感样本，在 0.15 命中、0.2 与 0.25 都不命中**
  —— 说它"免费修好了"是拿一个不合格的工作点换来的。
  它在 91% 工作点上仍然是"向量能命中而字面也能命中"的一条，见 §4 表。

也就是说，被当作"必须上向量"依据的三条里：一条是阈值敏感（且那个阈值现在
守不住空样本），另外两条**向量和字面一起失手**。立项理由在数据面前仍然
没有站住 —— **而且补样本之后，那条"靠调阈值就免费修好"的安慰也一并没了。**

### 4.2 向量新掉的两条，掉法不一样，但都很典型

- **`frac_unit_compare`**（"孩子坚持八分之一比五分之一大，理由是 8 比 5 大"）
  —— 字面版靠 `normalize_math` 把"八分之一"改写成 `1/8` 后直接命中
  "分数的意义"；向量版召回的是**"认识成正比的量"**。这是 dense 检索的
  经典失败形状：**主题相邻但事实错误**。它"懂"这句话在讲数与量的比较，
  但挑错了知识点。而且这种错误比空手而归更危险 —— 消费端 LLM 拿到一个
  看起来沾边的候选，可能当真。
- **`place_value_ignored`**（"数字写在哪一位都无所谓，6 就是 6"）
  —— 字面版在 0.15 命中"数位的含义"（"数位"二字直接对上）；向量版在 0.70 上
  **空手而归**。这条最讽刺：口语和术语的对应（"写在哪一位" ↔ "数位"）
  恰恰是语义模型该做的事，结果是字面匹配靠共享的两个字做到了。
  （补样本后字面在 0.25 上也丢了这条 —— 但它是被门槛挡掉的，不是被
  语义挡掉的：0.15 处的命中说明字面分数**排对了**，只是分数不够高。）

一个可推广的观察：**中文数学术语本身就是高度自解释的复合词**
（"数位""分数""交换律""质数"），家长的口语转述里往往原样带着这些词。
字面二元组匹配在这种语料上不是"没有语义"，而是**术语词形本身就承载了语义**。
向量模型把词形抹掉换成一个 1024 维的稠密表示，在这里是净损失。

### 4.3 排序维度：两边都是空的，而且更空的是向量

设计文档 §5 留了一个问题："若向量版的 @1 与 @3 拉开差距，说明它真的带来了
排序能力 —— 那会让『给 LLM 三个候选自己挑』这条设计理由第一次真正成立。"

**答案是否定的，而且补样本之后连那条微弱的正面证据也没了：**

- **字面 @0.25（本轮的同工作点，实跑）：@1 = @3 = @5 = 79%，三个数完全相同。**
  **排序维度在真正的工作点上是空的。**
- 字面 @0.15（91% 工作点）：@1 = 84%，@3 = @5 = **89%** —— 这里确实有
  1 条样本的 @1/@3 差距（`zero_not_even` 排在第二位命中）。这就是上一轮
  报的那条"唯一的正面证据"。
- 向量 @0.70（91% 工作点，上一轮数据）：@1 = @3 = @5 = **79%**，全空。
- 向量 @0.75（本轮同工作点）：**@1/@5 未取得**，不猜。

所以更新后的说法是：**"给 LLM 三个候选自己挑"这条设计理由，在本轮的同工作点
上一条证据都没有。** 上一轮那条唯一的正面证据（字面 @0.15 的 1 条样本）
**依附于一个现在守不住空样本的阈值** —— 它没有被推翻，但它站的那块地
已经不算数了。这是 §6.0 那条元教训的又一个落点：**一个结论的有效性，
上限是它所依附的那个工作点的有效性。**

## 5. 代价（四项，全部实测数字）

全部为本机实测，无估算。机器：Apple Silicon macOS，Python 3.12。

| 项 | 字面 | 向量（bge-m3） |
|---|---|---|
| **① 模型体积** | 0 | **4.3G**（`~/.cache/huggingface/hub`，下载前该目录不存在） |
| **② 依赖增量** | 0 | **+744M**（`.venv` 81M → 825M），29 个包，`uv sync --extra embed` 耗时 **9.5s** |
| **③ 建索引耗时** | **0.00s** | 见下方"两个口径"，**3.2s**（本轮）/ **~10.5s**（上一轮） |
| **④ 单次查询延迟** | **1.6ms** | **29.7ms**（新提问，含 1 次 encode）／ **12.0ms**（复查，纯余弦比对） |

**③ 的两个口径必须分开看，不要拿新数悄悄替换旧数：**

| 口径 | 数值 | 编码条数 | 说明 |
|---|---|---|---|
| **上一轮（2026-07-27）** | **~10.5s**（实测 9.8 / 10.4 / 10.6 / 10.9 / 18.3 / 23.5s） | 375 | 含更多首次开销；权重不在 OS page cache 时到 23.5s |
| **本轮（2026-07-28）** | **3.2s** | 383 | **模型已在本地缓存的热启动值** |

**两个数不是同一件事的两次测量，是两个口径**：本轮 3.2s 是彻底热的
（权重在 page cache 里、模型目录已完整），上一轮那个区间含冷/温启动。
**要引用"建索引要花多久"这个代价时，`~10.5s` 那档更接近真实首次体验，
`3.2s` 是理想下界。** 编码条数从 375 涨到 383 是 ground truth 从 22 条
补到 30 条带来的（**353 条语料 + 30 条观察句 = 383**），与耗时口径无关。

补充实测（以下为上一轮数据，本轮未重测）：

- **首次运行 vs 热启动**：首次要下 4.3G，实测 **>10 分钟**（第一次跑撞上
  10 分钟的执行超时被杀，彼时已落盘 2.1G；续跑补完）。全缓存后的热启动
  端到端 **27.1s**（含模型加载 + 编码 353 条语料 + 19 个阈值的完整扫描）。
  两者差值主要是下载，不是模型加载。
- **`encode_calls`**：上一轮 375 = 353 条语料 + 22 条观察句；本轮 383 =
  353 + 30。缓存生效，19 个阈值的扫描只编码了一遍语料。

### 5.1 四项之外，实测才发现的两笔账

**(a) 4.3G 里有一半是白拿的。** `BAAI/bge-m3` 主分支只有
`pytorch_model.bin`（2.27G），而 `transformers` 5.x 会**在后台线程里另抓
一份 `model.safetensors`（2.27G）**，来源是仓库的 PR 分支 `refs/pr/130`
（缓存里多出一个独立 snapshot 目录可证）。也就是说"下一个 2G 模型"实际
落盘 4.3G。

**(b) 那个后台线程会挂住进程退出 —— 实测卡了 9 分 50 秒。**
现象：结果全部打印完，进程不退。`sample` 抓栈显示主线程停在
`Py_FinalizeEx → wait_for_thread_shutdown`，等的是一个**非 daemon 的
`hf-xet` 下载线程**，那个线程卡在 `_dispatch_semaphore_wait_slow`。
诱因是缓存里残留的 `*.incomplete` 分片（我第一次跑被超时杀掉留下的）——
清掉孤儿分片后同一条命令 **27.1s 干净退出（EXIT=0）**。

这两笔都记在这里而不去"修"：它们是上游（`huggingface-hub` / `hf_xet` /
`transformers` 5.x）的行为，不是本项目的代码问题。但它们是**"多一个 GB 级
依赖"这句话的真实展开** —— 设计文档 §2 说"代价如实记"，这就是记法。

### 5.2 "全可测、零模型依赖"这条性质仍然成立

本轮结束时回到不带 extra 的环境重新验证：

```
uv sync          # 卸掉 sentence-transformers 及其 28 个传递依赖
uv run pytest -q # 396 passed
```

领域层的测试全部靠假 embedder 跑，**卸掉模型库后一个测试都不掉**。
这是 `Embedder` 协议那道边界唯一要证明的事，它证明了。

## 6. 诚实结论

### 6.0 本轮最贵的一条：**裁判本身太脆了 —— 那个判据的分母只有 3**

上一轮整个实验的公平性，压在一条纪律上：**不许各挑各的阈值，必须在
"空样本正确率 = 100%"这个相同工作点上比 recall@3。** 这条纪律是对的，
而且是关键的 —— 没有它，两条路线各报自己最好看的那个点，比较毫无意义。

**但那个用来锚定工作点的指标，当时的分母只有 3。**

而且那 3 条恰好都是"完全不相关"的容易样本（几何、钟表、背古诗）。
一个方法只要能对这三类说"不知道"，就拿到 100%，就被判定"站在了公平的
起跑线上"。补到 11 条之后，每一个基线数字都动了：

| | 3 条空样本（上一轮） | 11 条空样本（本轮） |
|---|---|---|
| 生产阈值 0.2 的空样本正确率 | 100% | **91%（10/11）** |
| 字面同工作点 | 0.15 | **0.25** |
| 字面 recall@3 基线 | 89% | **79%** |
| 向量同工作点 | 0.70 | **0.75** |
| 向量 recall@3 | 79% | **53%** |
| 两者差距 | 10pp（2 条） | **26pp（5 条）** |

**结论方向没变（向量仍然没赢），但这不该让人放松** —— 方向没变是运气，
不是纪律带来的保证。真正要记住的是：

> **纪律守住了"不许作弊"，守不住"指标本身没意义"。**
>
> 上一轮那套"不许换工作点、必须同工作点比较"的纪律本身是对的、而且是
> 关键的；**问题出在纪律用来锚定的那个指标当时太脆了**。
> 这是"小样本上的百分比要当心"这条教训第一次**不是发生在被比较的对象
> 身上，而是发生在裁判身上**。

上一轮已经很小心了：对 recall@3 那 19 条反复强调"±1 条 ≈ ±5.3pp"、
算了 McNemar、拒绝说"显著优于"。**那把统计谦逊的尺子，一次也没有量到
空样本正确率这个指标上。** 因为它当时不被当成"结果"，而被当成"实验装置的
一部分" —— **而实验装置是不会被审的东西**。

可推广的做法（已写进 §1.1 的补法）：

1. **凡是用来定义工作点 / 闸门 / 判定标准的指标，必须和被测指标受同等审查。**
   问同一个问题："它的分母是几？±1 条会让它跳多少？"
2. **判据类指标的样本要覆盖多个互斥类别，不能全是同一种容易样本。**
   3 条全是"完全不相关"，覆盖不到"偶然字重叠"这个真正的失败模式；
   补样本时按"其他领域 / 完全非数学 / 太笼统"分三类，才第一次把
   `empty_bar_chart` 这条 0.2105 的误招逼出来。
3. **先定分类、按分类写死样本、写完才第一次跑分数**（§1.1）。
   反过来做，就是用被测系统的输出去设计测它的集合。

### 6.1 "纯检索够不够用"第二次被数字回答：够，而且这次是被正面挑战之后

第一次（2026-07-27 上一轮）是被动的：recall@3 从 63% 修到 84%，靠的是修两个
实现缺陷，没有引入模型，闸门转绿。那次证明的是"还没到必须上模型的时候"。

**这一次是主动的**：真的把模型装上、真的下了 4.3G、真的在同一个工作点上
量了一遍。结果是 **79% vs 53%，字面赢 26 个百分点**（重扫后；重扫前是
89% vs 79% = 10 个百分点）。在两个工作点上都可比的那组数据里
（91% 工作点，§4），**向量零个独赢样本**。

所以答案不是"暂时够用"，而是：**在这份语料、这个任务上，dense 向量检索
是一次净退步。** ADR-0006 不但没被推翻，反而拿到了它成立以来最硬的一条
证据 —— 因为这是它第一次在"对手真的到场"的情况下赢的。

**补样本之后这条结论更稳了一点，但稳的方式值得说清楚**：不是"差距变大所以
更可信"（那是把 26pp 当成强度读，见 §6.3），而是**判据本身变结实了** ——
现在的"同工作点"是 11 条互斥类别的空样本压出来的，不是 3 条容易样本给的。
**结论的可信度来自判据的分辨率，不来自差值的大小。**

### 6.2 ADR-0006 的处理：不推翻，追加补记

设计文档和 ADR-0006 都写死了分叉：**若向量明显更好，ADR-0006 就该被推翻
并重写。** 现在不是那个分支，所以照另一条走 —— 在 ADR-0006 追加一条
"2026-07-27 向量对比补记"，记录它被正面检验过并通过。**两个分支都要写，
不是只有赢了才记**，否则记忆里只剩下成功案例，下次还会重新纠结一遍。

**假如结果反过来该怎么改**（写在这里，是为了证明这个判据在实验前就是
可执行的、不是事后编的）：若向量在同工作点上明显更高，需要新增 ADR-0007
取代 ADR-0006，把 `serve/scoring.py` 的默认打分器换成 `VectorScorer`、
`sentence-transformers` 从 optional 提升为主依赖、`min_relevance` 改为
余弦标度上的阈值、`mcp_server.py` 的默认路径切到向量，并接受
"MCP server 启动要加载 2G 模型、CI 要下模型"这三笔账。**这三笔账现在
不用付了**，这本身就是本轮最大的收益。

### 6.3 但是：26 个百分点在 n=19 上仍然不是"显著提升"，这一点对我自己也适用

19 条计分样本，**±1 条命中 ≈ ±5.3 个百分点**。79% vs 53% = 15/19 vs 10/19，
**差 5 条样本**。

**5 条比上一轮的 2 条实，但它没有把这个实验从"小样本"里救出来。**
n 还是 19，一条样本仍然值 5.3 个百分点，**换掉两三条 ground truth 就能
让 26pp 变成 15pp 或 35pp**。差距变大不等于证据变强 —— 变强的是判据
（§6.1 末），不是这个差值。

**本轮做不了配对检验**：McNemar 需要两条路线在同一批样本上的逐条判定，
而向量 @0.75 的逐条明细本轮没取（§4 口径说明）。上一轮在 91% 工作点上
算过一次：不一致样本 2 条（字面赢 2、向量赢 0），**p = 0.5，统计上完全
区分不开** —— 那个结果仍然有效，但它对应的是 10pp 那对数字，
**不能拿来给 26pp 背书，也不能拿来否定它**。

所以我**仍然不能**说"字面显著优于向量"。能说的是：

1. **向量没有赢。** 在能拿到的全部证据下，它至少没有比字面更好；
   而且这个结论在两个独立的工作点（91% 与 100%）上方向一致。
2. **而代价是确定的、巨大的、可精确计量的**（§5：4.3G + 744M + 建索引
   0→3.2~10.5s + 查询 1.6ms→12~30ms）。
3. **收益不确定而代价确定时，答案是不买。** 这不是统计问题，是决策问题。
   要论证买下它，需要的是"显著更好"，而不是"区分不开"。

同一把尺子继续用在自己身上：

- §3.2 那条"生产默认值 0.2 有一条已知误招"是 **1/11**，不是"生产阈值不合格"。
- §3.1 那两层基线更正说明的是**判据在变**，不是"字面变差了" ——
  字面在 0.25 上的能力和上一轮在 0.25 上一模一样（recall 列一个数没变）。
- **别把 84% vs 89% 讲成提升，别把 89% vs 79% 讲成碾压，
  更别因为它现在是 79% vs 53% 就改口讲碾压。**

### 6.4 这个结论的边界（它不是"RAG 没用"）

本轮量的是**一个特定组合**，把结论外推出去就是耍赖：

- **只测了 dense 单路。** bge-m3 自带 sparse 与 ColBERT 多向量输出，本轮
  一个没用（设计文档 §6 明确不做 hybrid）。
- **只测了一个模型**（bge-m3），没试 `Qwen3-Embedding-0.6B` / `voyage-4-nano`。
  模型名是参数，换一个是一行改动 —— 但换之前应该先问 §6.5 那个问题。
- **没做 rerank、没做 chunking、没做微调、查询侧没加 instruction 前缀**
  （bge-m3 dense 不要求前缀，但这仍是一个没拉的杠杆）。
- **语料只有 353 条短文本、64 个节点。** 规模上去之后字面匹配的
  O(n) 全量比对和二元组的区分度都会先撑不住；这个结论有明确的规模上界。
- **ground truth 只有 30 条（19 计分 + 11 空样本），而且 11 条空样本里
  刻意排除了两类**（"领域内但图没覆盖"、"说的是对的"，见 §1.1）。
  也就是说，**这道门槛守的是"完全不沾边"，还没测过"沾边但不该召回"** ——
  后者才是真实使用中更常见、也更难的一类。3 条不够，11 条只是够到了
  下一个台阶，不是够了。
- **§5 的延迟数字（12.0ms / 29.7ms）里，大头是实现成本，不是向量检索的
  固有代价。** `scoring.py` 的 `_cosine` 是三层纯 Python 生成器表达式，一次
  `match_misconceptions` 要做 75×3 = 225 次调用、每次 1024 维——这段 CPython
  解释器开销才是 12ms 的主要来源。换成一次 numpy 矩阵乘法是亚毫秒级，差两个
  数量级。**这条限定不削弱结论**：真正不可压缩、决定"向量没有赢"的是①模型
  体积、②依赖增量、③建索引耗时这三笔——它们是装上一个 embedding 模型必然
  要付的代价；单次查询延迟这一项则是本实验实现绑定的数字，向量化后可以
  基本抹平，不该被当成向量路线的固有短板去反对它。

诚实的说法是：**"在 353 条中文数学术语短文本上，开箱即用的 dense 单路
向量检索打不过一个带数学表达归一化的双向 gram 覆盖率。"** 不是
"向量检索没用"。

### 6.5 真正的收获，可能不是这两个数字

（本轮之后，"真正的收获"有了第二个、而且更贵的候选 —— 见 §6.0。
这一节记的是上一轮那个。）

回头看 §4.1：立项时被点名"必须上向量才能救"的三条样本，**一条是阈值敏感
（而那个阈值现在守不住空样本），另外两条向量和字面一起失手**。

这说明立项理由本身是靠直觉下的诊断 —— "字面匹配在换数字时会废"这句话
听起来太对了，对到没人（包括我）想去验证"那向量就不会废吗"。
**这次实验最贵的部分（4.3G 下载 + 装依赖 + 跑通）买到的不是一个更好的
检索器，而是一次对自己诊断的证伪。**

它和上一轮那条"IDF 加权实测更差"是同一类记录：**一个听起来无懈可击的
改进方向，实测是负收益。** 这类记录比成功的调优值钱，因为直觉会重复
产生同一个想法，而数据只在被真的采集时才拦得住它。

对应到心法②"尽可能久地保持简单"：这条原则的操作化版本不是"不要用复杂
方案"，而是 **"上复杂方案前，先让它和简单方案在同一个工作点上比一次"**。
本轮的全部纪律（同工作点、只动一个变量、字面基线现算不写死、够不到工作点
就报 None 并非零退出）都是为了让这一次比较没法作弊 —— 包括没法被我自己
作弊。**2026-07-28 补一句：这句话现在要带个后缀 —— "……而且要定期检查
那个工作点是用几条样本定出来的"（§6.0）。**

### 6.6 遗留与下一步

- **不改生产路径**：`MCP server` 仍走字面检索，`LiteralScorer.min_relevance`
  仍是 0.2，聚合权重不动。本轮是实验，不是切换。
- ~~**开放问题：0.2 还是 0.25？**~~ **[2026-07-28 已决定：留在 0.2]**
  （**不是**上一轮那个 0.15 vs 0.2 了）0.2 现在有一条实测的误招
  （§3.2，`empty_bar_chart`，相关度 0.2105），0.25 是 11 条空样本下 100%
  正确率的起点、代价是 recall 从 84% 降到 79%（掉的两条是从命中变成空手
  而归，不是变成误召）。**选了 0.2，那条误招被接受为已知代价** ——
  这次两边都不是白拿，没有上一轮那种"免费的 5 个百分点"。
  **重开条件**：11 条空样本只压过"完全不沾边"，还没压过"沾边但不该召回"
  （见 §1.1 刻意排除的两类）；补上那类样本后若 0.2 的误招不止这一条，
  这笔账重算。两栏账见 `docs/rag-vs-literal-backlog.md`。
- **向量侧在新工作点（0.75）的逐条明细还没取**。取它需要
  `uv sync --extra embed`，本轮为保住"零模型依赖"这条性质的干净验证没做。
  想补的话就一条命令：`--scorer vector --min-relevance 0.75`。
  在那之前，§4 的向量列只能标着"上一轮 @0.70"读。
- **`--scorer vector` 保留**：它是一条可复现的对照路径，成本只有一个
  optional extra。**换模型是一行**（`--model` 参数）；**hybrid 不是** ——
  见下一条。
- **想再推进向量路线的话，理论上下一个受控变量该是 hybrid（dense + 字面）**：
  §4.2 显示两者的失败模式**不重合**（向量丢的 `place_value_ignored`
  字面稳稳命中），融合有理论收益。**但现有协议做不了排名融合**：真正想要
  的 hybrid 是 RRF 之类的**排名融合**，需要打分器看到整个候选集合、产出
  有序列表；而现协议下 `Scorer.relevance(query, target) -> float` 永远只看
  一对文本，压根拿不到候选集。剩下能做的只有 `max(literal, w*cosine)`
  这种**分数融合**，这又撞上本仓库自己在 `scoring.py` 开头写的洞见——
  余弦和覆盖率标度完全不同，两个不可比的分数没法共用同一个 `min_relevance`
  闸门。**先扩协议**（或换成 §6.7 说的 `Retriever` 形状）**才谈得上 hybrid**，
  不是加一个参数那么简单。
- **真正的瓶颈仍然不在检索**：19 条里字面在生产默认值 0.2 上命中 16 条、
  在同工作点 0.25 上命中 15 条，未命中的都是"抽象规则 vs 具体数字"或
  被门槛挡掉的边缘分。而规划线因为图只有 31 条边、26/64 孤立
  **完全不可用**。把 4.3G 花在检索上、让图继续稀着，是优化错了地方。

### 6.7 给下一个接手的人

现在的 `Scorer` 协议（`relevance(query, target) -> float` + `min_relevance` +
`warm(corpus)`）是一个**成对打分**的实验台，不是检索器 —— 它支持"换打分
函数"（字面 ↔ 向量）和"扫阈值"，但不支持 top-k 检索、ANN 索引、排名融合。
`GraphIndex.search_topics` / `match_misconceptions` 自己做全量线性扫描
再排序截断，`Scorer` 从头到尾看不到候选集。

若下一步真要做 hybrid（见 §6.6），第一件事不是调参数，是决定要不要把这层
换成 `Retriever(query, k) -> list[(id, score)]` 这种看得到候选集的形状。
而这一步会**重新引出"聚合权重放哪一层"的问题**——现在 `DESCRIPTION_WEIGHT`
/ `SECONDARY_WEIGHT` 这套按字段加权、按阈值截断的逻辑，是写在
`query.py` 里、假设打分器只看一对文本才成立的；换成 `Retriever` 之后，
这套聚合还成不成立、该不该整个搬进新协议，是本轮受控性的根基，值得先
想清楚再动手，不要边写边决定。
