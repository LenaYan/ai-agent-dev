## 一、Marble 数据的定量核对

clone 仓库后对全量数据跑校验（数据版本 v1，生成于 2026-07-08）：

| 检查项 | 结果 |
|---|---|
| 节点 / 边 / 学科 | 1590 / 3221 / 8（Math 503、Science 547、English 286…） |
| 有向环 | **0** |
| 悬挂引用 | **0** |
| 孤立节点 | **0 / 1590** |
| 年龄倒挂（前置比后继晚） | 56 条（1.7%），其中 hard 边仅 8 条 |
| 缺 assessmentPrompt | 0 |
| 缺 evidence criteria | 35 |
| **缺课标对齐** | **772 / 1590 = 48.6%** |

**两个关键判断：**

**1. 图工程这一层扎实，别低估。** 0 环 0 悬挂 0 孤立不是随手能达到的，说明有自动校验。

**2. 但内容层有问题，且宣称与事实有差距。** 手工核对发现 `name` 字段不可靠：

| 节点 ID | name 写的 | description 实际是 |
|---|---|---|
| `mt_MCu_SNg_OW` | Arrays for multiplication | 四位数除以一位数的短除法 |
| `mt_GzcJEVkNRn` | Understanding angles | 用边长相乘求长方形面积 |
| `mt_Xt1cRqaBOW` | Understanding angles | 四边形的分类 |
| `mt_H6LlpWgEYS` | Reading and Comparing Bar Graphs | description 说条形图，assessmentPrompt 却问折线图 |

另有 10 组同名节点跨 domain 分布。而其 `PROVENANCE.md` 通篇讲授权与许可，
**完全没有生产方法与 QA 流程说明**。

**这个区分（结构层 vs 内容层）后来直接决定了校验层的分层设计。**

第二条更重要：**宣称"对齐国家课标"，实际只有一半节点做到**。这个数字说明
**对齐工作有多贵** —— 一个有团队、全职做的项目也只完成了一半。

## 二、可行性分析：四道闸门

### 闸门 1：法律 —— 风险可控，但必须分清两样东西

| | 课程标准条目 | 教材内容 |
|---|---|---|
| 例 | "能进行简单的小数加减运算" | 人教版四下第四单元的例题、习题、编排 |
| 发布主体 | 教育部 | 人教社等（商业出版物） |
| 著作权状态 | 大概率属《著作权法》第五条排除范围 | **明确受保护，维权积极** |
| 可否使用 | 引用编号 + 要求描述，风险低 | ❌ 绝对不要抄 |

⚠️ **不确定性声明**：中国课标是否落入第五条"具有行政性质的文件"，
缺明确司法判例（知识截止 2026-01）；人教社出版的课标单行本另有版式设计权。
**真做之前应取得书面法律意见。**

**新型风险**：LLM 训练数据可能含教材内容，生成描述可能与教材实质性相似 ——
自动化解决不了，只能靠人工改写兜住。

**中国特有负担 —— 双层对齐**：中国教学实际由教材驱动而非课标驱动，
家长和老师认"人教版四下第四单元"，不认"学段目标 2.3"。

### 闸门 2：教研 —— 真正的瓶颈

**"A 是不是 B 的前置"，谁来判断？**

依赖边的正确性**没有形式化验证方法**。图无环、年级单调，CI 都能查；
但"学分数加法前必须先掌握等分"对不对，只有教过书的人知道。

LLM 生成的依赖边看起来都很合理，**而这正是危险所在** ——
错误是静默的，一条错边把整条学习路径导偏，用的人发现不了。

| 方案 | 成本 | 可行度 |
|---|---|---|
| 付费请教研员审核 | 60h × 200-400 元/h ≈ 1.2-2.4 万 | 高，但要找到人 |
| 师范院校课程与教学论方向研究生 | 低（可作研究素材） | 中，质量参差 |
| 开源邀请贡献 | 0 | 低，冷启动难 |
| 自己 + LLM 多视角交叉审核 + **明确标注未经教研审核** | 0 | MVP 唯一现实选项 |

### 闸门 3：工程 —— 最不成问题的一环

```
课标文本 → 条文切分与结构化（规则 + LLM）
    ↓  候选 micro-topic 抽取（按学段 × 领域并行）
    ↓  去重合并（embedding 聚类 + LLM 裁决）
    ↓  依赖边生成（只在同领域/相邻学段内提候选，控制组合爆炸）
    ↓  交叉审核（多视角独立投票：认知顺序 / 教学实践 / 反例检验）
    ↓  CI 校验层   ← 本次已完成
```

### 闸门 4：需求

国内做"知识图谱 + 自适应"的不少（松鼠 AI 一挂做了十年），
但**开源的、为 LLM 消费设计的、对齐中国课标的**未见成熟方案。位置是空的。

### 工作量估算

MVP = 小学数学「数与代数」1-6 年级（约 150 节点、300 条边）：

| 环节 | 工时 |
|---|---|
| Schema 设计 + CI 流水线 | 8h ← **本次完成** |
| 课标文本获取与结构化 | 6h |
| 多 agent 生成流水线 | 16h |
| 依赖边生成 + 交叉验证 | 12h |
| 人工审核（自审） | 20h |
| MCP server + 文档 | 10h |
| **合计** | **~72h** |

全学科全学段（对标 1590 节点）：保守 600-900 小时 + 教研审核费用。

## 三、核心决策：定位为「流水线」而非「数据集」

三个目标层次，答案完全不同：

| 目标 | 判断 |
|---|---|
| 给自己孩子用 | ❌ 不值得。72 小时换单用户数据集，投入产出不成立 |
| **AI Agent 开发练手** | ✅ **选这个。** 任务形状命中要练的东西，且输出**可被机器校验** |
| 做成开源项目/产品 | ⚠️ 先解决：(a) 教研员审核背书 (b) 法律意见。否则沙上盖楼 |

**决策：按第 2 条做，但按第 3 条的标准设计 schema 和 provenance**，将来升级不用推倒重来。

**关键认知**：这个项目的**真正资产是流水线，不是数据集**。
数据集可信度取决于教研审核，那一环靠工程补不上；而"从非结构化文本生成并
自校验结构化知识图"这条链是可复用能力，换个领域（法规、内部文档、合规要求）立刻能用。

按这个定位，教研审核不到位不再是致命伤，而是一个诚实标注的已知局限。

## 四、已交付：schema + CI 校验层

`practice/cn-curriculum-graph/`，全程 TDD，38 个测试通过。

### 相对 Marble 的四处刻意差异（逐条决策见 `docs/schema-design.md` D1-D8）

1. **`misconceptions`** —— 典型误概念，三段式（孩子会怎么想错 / 诱发提问 / 纠正切入点），
   因为 LLM 要用它做三件不同的事：识别、验证、纠正。Marble 完全没有。
   这是诊断类应用最值钱的部分 —— 有先修图只能答"下一步学什么"，
   有误概念才能答"他为什么这么想"。
2. **`revisits` 螺旋边** —— 中国课标是明确的螺旋结构（分数：三上→五下→六上）。
   这不是先修关系（本来就是同一概念），扁平 DAG 表达不了。
   约束：必须指向更高年级，且不参与先修边的环检测。
3. **每节点 `provenance`** —— method / review_status / reviewer / confidence。
   `MISSING_PROVENANCE` 定为 **ERROR 而非 WARNING**，宁可 CI 一开始就红，
   也不要养成"先攒数据、回头补来源"的习惯 —— 那种债事后一定还不上。
4. **双层对齐** —— `standards`（课标条目）+ `textbook_units`（教材单元）。
   **法律约束落进结构**：`Standard` 只有 curriculum + code，
   **没有存条目原文的字段** —— codes-only 不靠纪律保证，靠 schema 保证。

另用**年级（1-9）**而非年龄作为进度基元。

### 9 条校验规则

| 规则 | 严重级 | 理由 |
|---|---|---|
| `CYCLE` | error | 先修边有环 = 学不动的死循环 |
| `DANGLING_REF` | error | 边指向不存在的节点 |
| `ISOLATED_TOPIC` | warning | 通常是抽取流水线漏接边 |
| `GRADE_INVERSION` | hard=error / soft=warning | 依据：Marble 56 条倒挂里 48 soft、8 hard，一刀切必然过噪或漏报 |
| `REVISIT_NOT_ADVANCING` | error | 螺旋边没指向更高年级 = 接反了 |
| `LOW_STANDARDS_COVERAGE` | error | 宣称"对齐课标"必须能被卡住 |
| `MISSING_PROVENANCE` | error | 无法判断某条数据可不可信 |
| `NAME_DESC_MISMATCH` | error | 名实不符，纯规则查不出 |
| `CONSISTENCY_SKIPPED` | warning | 显式声明哪项没跑 |

### 三条设计要点

**1. 规则能查的和查不了的，分层设计。**
结构层纯规则即可（Marble 这层做得扎实）；真出问题的是内容层，
只能靠语义判断 → judge 做成 `Protocol` 依赖注入，
CI 接真 LLM，测试接确定性假判定器。

**2. "跳过"必须留痕。**
不传 judge 时产出 `CONSISTENCY_SKIPPED` 警告而非静默通过 ——
否则"CI 绿了"会被读成"全都查过了"，**这正是 Marble 让人误判其数据质量的方式**。

**3. `extra="forbid"` 全局开启。**
未知字段静默通过是数据集腐化最常见的入口。代价：schema 演进时旧数据立刻报错 —— 这是想要的行为。

### 校验层已被真实数据验证

对 Marble 全量数据（1590 节点 / 3221 边）运行：

```
1598 error, 36 warning
✗ MISSING_PROVENANCE × 1590
✗ GRADE_INVERSION × 7            （hard 边年级倒挂）
✗ LOW_STANDARDS_COVERAGE × 1     （对齐率 51.4%，772/1590 未对齐）
! GRADE_INVERSION × 35           （soft 边）
! CONSISTENCY_SKIPPED × 1
```

**772 这个数字独立复现了先前手工核对的结果** —— 校验层确实在工作的证据，不是自说自话。
（年龄→年级映射有损，按年龄算的 8 条 hard 倒挂在这里显示为 7 条。）

## 五、跑真实数据暴露的两个自身 bug

单测 34 个全绿之后跑 Marble，当场暴露：

**Bug 1：报告按 `code` 单键分组，把 error 藏进了 warning 组。**
`GRADE_INVERSION` 在 hard 边是 ERROR、soft 边是 WARNING，
按 code 分组后用 `group[0].severity` 决定整组标记，7 条 error 被显示成 warning。
→ 改为按 `(code, severity)` 复合键分组。

**Bug 2：适配器漏映射 `standards`，把对齐率虚报成 0%。**
这会构成对 Marble 的错误指控（真实是 51.4%）。
→ 补上映射（其格式是 `"课标标识:条目编号"` 字符串）。

两个都是**先补失败测试再修**的。

**教训**：单测没抓到 Bug 1，因为测试数据里同一 code 严重级相同。
**分组键必须覆盖所有影响展示的维度；跑真实数据是最好的测试。**
