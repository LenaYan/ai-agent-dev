# 流水线的可复现性：同一份输入跑三次，图对不上

> 2026-07-28。起因：修完边审核的输入 bug 后重跑流水线，24 个评测标签里
> 12 个的节点 id 失效。追下去发现的问题比标签失效大得多。

## 一句话

**同一份课标原文、同一套代码、四层全都 `temperature=0`，跑三次得到三张对不上的图**
——两两之间节点名 Jaccard 只有 29%~52%。而**这个动荡里约七成不是内容变了，是名字被改写了**，
配上"id = 名称的哈希"这个设计，就变成了节点身份的全面洗牌。

## 怎么量的

三次独立抽取：A（2026-07-27 那轮）、B（2026-07-28 修完边审核后重跑）、
C（当天只跑抽取层的第三次）。都用 `deepseek-v4-flash`、`temperature=0`、同一份
`01-chunks.json`（切分是纯规则的，三次完全相同）。

| 配对 | 节点名 Jaccard | 同名节点 | 误概念字面相关度中位数 | 低于生产门槛 0.2 |
|---|---|---|---|---|
| A-B | 52% | 48 | 0.433 | 25% |
| A-C | 32% | 36 | 0.380 | 22% |
| B-C | 29% | 32 | 0.500 | 16% |

## 两个失败模式，性质完全不同

### ① 整块 chunk 颗粒无收，而且每次是不同的几块

28 个 chunk 里 **8 个（29%）至少有一次产不出任何 draft**：

```
#001 缺席 B ｜ #004 缺席 A/B ｜ #005 缺席 B ｜ #006 缺席 A
#010 缺席 A/B ｜ #016 缺席 A/B ｜ #019 缺席 C ｜ #025 缺席 C
```

这是最大的一块损失——整组知识点连同它们的误概念一起消失。落在
`dropped.json` 里是 `NO_DRAFTS`，**留痕了，但没人看**。

### ② 命名的同义改写（占身份动荡的大头）

三次都有产出的 20 个 chunk 里，只有 10 个的名称集合完全一致。但差异的形状是这样的：

```
比较万以内数的大小   vs  万以内数的大小比较        ← 词序
探索并掌握多位数乘法  vs  探索并掌握多位数的乘法     ← 一个"的"
了解十进制计数法     vs  十进制计数法              ← 去掉动词
初步的应用意识       vs  初步形成应用意识
用计算器探索简单规律  vs  借助计算器探索简单规律
计数单位的感悟       vs  计数单位
```

量化：A 有而 B 没有的 22 个名称里，**14 个（64%）能在 B 里找到字面相似度 ≥0.6
的对应项**；B→C 这个比例是 **80%**（32/40）。相似度 1.00 的那些是完全包含关系
（"计数单位的感悟" ⊃ "计数单位"）。

**也就是说：内容大体是稳的，抖的是措辞。**

## 根因：用名称的哈希做节点身份，把措辞抖动放大成身份变更

```python
def make_topic_id(content: DraftContent) -> str:
    """确定性 id：重排输入不改变结果，便于比对两次跑的差异。

    取 (name, domain, grade_start) 而非序号，是为了让 id 在增删条目时保持稳定。
    """
    seed = f"{content.name}|{content.domain}|{content.grade_start}"
    return "t_" + hashlib.sha1(seed.encode("utf-8")).hexdigest()[:10]
```

这个设计**防的是"增删条目导致序号平移"**——docstring 写得很清楚。问题在于：
实测下来占主导的动荡**不是增删，是改写**，而名称哈希对改写零抵抗力。

**为一种威胁做了防护，而现实中占主导的是另一种。** 这不是写这段代码时能预见的
——它需要"同一输入跑三次再比对"这个动作，而那个动作直到今天才第一次做。

## 单次调用其实相当稳，不稳的是跨运行

同一个 chunk 连发三次（`temperature=0`）：3 个 chunk 里 2 个的**名称集合三次完全一致**，
只有误概念文本在变；第三个（#006）名称不一致，差异是切分粒度
（"体会数和运算的意义" 1 个 vs 拆成"在生活情境中体会数的意义"+"…运算的意义" 2 个）。

所以"模型完全随机"这个说法是不对的。更准确的说法是：**措辞与切分粒度处在一个
浅的势阱里，同一次会话内倾向一致，跨会话/跨天会漂**。（`temperature=0` 对
MoE 架构不保证确定性——路由与批处理都会引入非确定性——但这里的漂移幅度
远大于纯采样噪声能解释的范围。）

## 这件事的射程

**没有被推翻的**：字面 vs 向量那轮受控对比仍然有效。那轮**把图固定住、只换打分器**，
是干净的单变量对比，79% vs 53% 不受影响。

**被推翻的**：任何**跨重跑**的 recall 比较。"新图比旧图掉 17 个百分点"这句话里，
有多少是边审核修复的副作用、有多少是抽签，说不清。

**新暴露的**：这个项目的立项理由是"真正的资产是流水线，不是数据集"
（见 `feasibility-analysis.md`）。而一条依赖图如果每次生成都换掉一半节点身份，
**下游没法在它上面建任何东西** —— 评测标签活不过一次重跑只是最先撞上的那个症状。
这直接冲击"流水线可复用"这个前提，需要正面回答。

## 一条方法论

这次的教训和本仓库反复撞的那条是同一个：**先确认度量在量你以为它在量的东西。**

前几次是"长度惩罚冒充模型问题"（recall 63%）、"空样本分母只有 3"、
"边审核缺输入冒充模型能力差"。这次是**"抽签结果冒充质量变化"**：
两张图的 recall 差 17 个百分点，看起来像是某个改动的效果，实际上重跑一次就能
摆动同样的幅度。

可推广的规则：**任何跨运行的数字对比，先证明这条流水线是可复现的。**
在此之前，所有"改了 X 之后指标变化 Y"的结论都欠一个前提。

## 追查 ①（`NO_DRAFTS`）的结果：逃生舱被误用，重试即可，与模型强弱无关

**排除的假设**（都是先量再排，不是猜）：

- **不是长度**：不稳的 chunk 中位 42 字，稳的 40 字，范围完全重叠。
- **不是调用失败**：extract 阶段的丢弃里 9 条 `NO_DRAFTS`、只有 1 条
  `EXTRACT_FAILED` —— 模型**确实返回了空列表**，不是 API 出错。
- **不是模型不够强**：同一 chunk 连发 5 次，`deepseek-v4-flash` 与
  `deepseek-v4-pro` 的空返回率没有差别（pro 在 #004 上还更高，2/5 vs 1/5）。
  **换模型解决不了。**

**根因**：`_SYSTEM` 里那句"如果拆不出任何可教的知识点，返回空列表"是个逃生舱，
而它被误用在明显可教的内容上 —— #004 的原文是"探索加法和减法的算理与算法，
会整数加减法"。每次调用约 20~40% 概率走这个逃生舱。

**修法**：空返回重试（`EMPTY_RETRIES = 2`，即最多试 3 次）。

**为什么这不是"逼模型硬凑"**：素材里 28 条逐条读过，全部是实打实的课标条目，
没有一条拆不出可教的知识点。所以空返回一律是误判。仍设上限、且全空时照常记
`NO_DRAFTS`，并在 detail 里写明试了几次 —— 将来素材里真有空条目（比如章节标题
被误切成 chunk）时它还是会被如实记下来。

### 一个被证伪的怀疑，记下来免得重来

加完重试的第一轮里 #004 连空 3 次，当时怀疑**重试发的是逐字相同的请求、
撞上了服务端缓存**（若成立，加重试次数无效，得给请求带扰动）。

**实测证伪**：对 #004 跑 8 轮重试 ——

| | 基础空返回率 | `P(空 given 上一次空)` |
|---|---|---|
| 原样重试（请求逐字相同） | 2/10 = 20% | **0/2 = 0%** |
| 带扰动重试（附尝试序号） | 1/9 = 11% | 0/1 = 0% |

若真被缓存粘住，这两个条件概率应该接近 100%。（条件样本只有 2 与 1 个，
证据强度有限，但方向明确反对粘滞。）

而"连空 3 次"根本不需要额外解释：基础率 20% 下单 chunk 连空三次是 0.8%，
**28 个 chunk 里至少出现一个的概率是 1-0.992^28 ≈ 20%** —— 一轮里撞上一个是正常的。
这也是上限定在 2 就够的理由：期望每轮残留不到 1 个 chunk。

### 没有宣称的东西

带重试跑一轮，覆盖 26/28。**这不构成"改进幅度"的证据** —— 此前三次运行的覆盖
分别是 24/23/26，这次落在同一范围内，而本文前半段刚证明单次运行的方差足以吞掉
这种差异。**不能在自己的改动上放宽刚给别人定的标准。** 能说的只有：机制对
（三次全空的期望概率降到个位数百分比）、记账变清楚了（"重试过仍空"与"一次就空"
现在可区分）。要证明幅度，需要带重试连跑三次再比 Jaccard。
