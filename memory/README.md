# memory/ — 跨会话记忆运维规则

这些文件是本工作区的**长期记忆**，让 AI 助手在新会话里也能接上下文。
它们是**给人和 AI 共同读写的结构化事实**，不是流水账。

> **三套记忆的分工**：本目录是**项目事实的唯一事实来源**（工作区级、可版本化、两个工具共读写）。
> Copilot 的 `/memory` 与 Claude Code 自带的持久记忆是**工具私有**的，只放各自的工具偏好和指向本目录的指针；
> 项目相关的事实（进度、决策、术语、坑）一律写这里——否则两个工具"记得的东西"会悄悄发散。

## 何时更新（AI 与我都应遵守）

| 触发 | 写入文件 |
|---|---|
| 学完一个主题 / 完成一次实践 | `learning-log.md` |
| 做出选型或方案决策（含被否决的） | `decisions.md` |
| 学到关键术语 / 概念 | `glossary.md` |
| 踩到值得记的坑 + 解法 | `pitfalls.md` |

## 写入原则

1. **追加优先，不轻易删除**：过时内容标注 `[已过时 YYYY-MM-DD]` 而非删掉，保留演进痕迹。
2. **每条带日期**：便于判断时效（Agent 生态变化快）。
3. **简洁可检索**：一条一个要点，避免长篇；能一句话说清就别写一段。
4. **决策要有理由**：`decisions.md` 每条必须包含"为什么"和"当时的取舍"。
5. **AI 更新后要告知**：在回复末尾注明"已更新 memory/xxx"，方便我复核。

## 给 AI 助手的使用方式

- 新会话开始处理实质任务前，可先浏览本目录了解已有进度与决策。
- 不要与已有决策冲突；若要推翻旧决策，在 `decisions.md` 追加新条目并引用旧条目编号说明原因。
- 记忆是事实沉淀，不是待办清单；待办用会话内 todo 或 `notes/`。
