# 可行性分析：建一个中国课标版的知识依赖图数据集

> 日期：2026-07-24
> 来源：本分析源自另一工作区（`~/Claude/child_watch_baobao`）对 Marble Skill Taxonomy
> 的产品分析，原文见该项目 `sessions/2026-07-24-marble-taxonomy-analysis.md`。
> 这里保留与本项目相关的部分。

## 结论

技术上完全可行，法律上有可控风险，**但真正的瓶颈是教研审核 —— 这一环靠工程补不上**。

因此本项目重新定义了目标：不做"中国版 Marble 数据集"，做**一条能生成并自校验
知识依赖图的多 agent 流水线**，用小学数学当验证领域。理由见第五节。

---

## 一、先看 Marble 做到了什么水平

对其全量数据跑结构校验（2026-07-24，数据版本 v1 / 生成于 2026-07-08）：

| 检查项 | 结果 |
|---|---|
| 有向环 | **0** |
| 悬挂引用 | **0** |
| 孤立节点 | **0 / 1590** |
| 年龄倒挂 | 56 条（1.7%），其中 hard 边仅 8 条 |
| 缺 assessmentPrompt | 0 |
| 缺 evidence criteria | 35 |
| **缺课标对齐** | **772 / 1590 = 48.6%** |

**两个结论：**

1. **图工程这一层扎实，别低估。** 0 环 0 悬挂 0 孤立说明有自动校验。
   此前发现的 name/description 名实不符是**内容层**问题，不是结构层 ——
   这个区分决定了本项目的校验层怎么分层设计。

2. **宣称"对齐国家课标"，实际只有一半节点做到。** 这个数字说明**对齐工作有多贵**：
   一个有团队、全职做的项目也只完成了一半。中国版只会更重（双层对齐）。

## 二、四道闸门

### 闸门 1：法律 —— 风险可控，但必须分清两样东西

| | 课程标准条目 | 教材内容 |
|---|---|---|
| 例 | "能进行简单的小数加减运算" | 人教版四下第四单元的例题、习题、编排 |
| 发布主体 | 教育部 | 人教社等（商业出版物） |
| 著作权状态 | 大概率属《著作权法》第五条排除范围（具有行政性质的文件） | **明确受保护，维权积极** |
| 可否使用 | 引用编号 + 要求描述，风险低 | ❌ 绝对不要抄 |

⚠️ **不确定性声明**：中国课标是否落入《著作权法》第五条，缺明确司法判例
（分析者知识截止 2026-01）；且人教社出版的课标单行本另有版式设计权。
**真做之前应取得书面法律意见。**

**实操策略（已落入 schema）**：`codes-only` —— `Standard` 模型只有
`curriculum` + `code` 两个字段，**不存条目原文**。与 Marble 对
NGSS / C3 / IB PYP 的处理一致（其 PROVENANCE.md 明说是拿不到授权）。

**新型风险**：LLM 训练数据可能含教材内容，生成的描述可能与教材实质性相似。
自动化解决不了，只能靠人工改写环节兜住。

**中国特有负担 —— 双层对齐**：中国教学实际由教材驱动而非课标驱动，
家长和老师认"人教版四下第四单元"，不认"学段目标 2.3"。
故 schema 同时有 `standards` 和 `textbook_units` 两层坐标。

### 闸门 2：教研 —— 真正的瓶颈

**"A 是不是 B 的前置"，谁来判断？**

依赖边的正确性**没有形式化验证方法**。图无环、年级单调，CI 都能查；
但"学分数加法前必须先掌握等分"对不对，只有教过书的人知道。

这不是靠 LLM 能绕开的。LLM 生成的依赖边看起来都很合理，**而这正是危险所在** ——
错误是静默的，一条错边把整条学习路径导偏，用的人发现不了。

| 方案 | 成本 | 可行度 |
|---|---|---|
| 付费请教研员审核 | 60h × 200-400 元/h ≈ 1.2-2.4 万 | 高，但要找到人 |
| 师范院校课程与教学论方向研究生 | 低（可作研究素材） | 中，质量参差 |
| 开源邀请贡献 | 0 | 低，冷启动难 |
| 自己 + LLM 多视角交叉审核，**明确标注未经教研审核** | 0 | MVP 唯一现实选项 |

MVP 走第 4 条，但**必须显式标注**。这已落入 schema：
`Provenance.review_status` 默认 `unreviewed`，且 `MISSING_PROVENANCE` 是 CI 硬错误。

### 闸门 3：工程 —— 最不成问题

```
课标文本 → 条文切分与结构化（规则 + LLM）
    ↓
候选 micro-topic 抽取（按学段 × 领域并行）
    ↓
去重合并（embedding 聚类 + LLM 裁决）
    ↓
依赖边生成（只在同领域 / 相邻学段内提候选，控制组合爆炸）
    ↓
交叉审核（多视角独立投票：认知顺序 / 教学实践 / 反例检验）
    ↓
CI 校验层  ← 本次已完成
```

### 闸门 4：需求

国内做"知识图谱 + 自适应"的不少（松鼠 AI 一挂做了十年），
但**开源的、为 LLM 消费设计的、对齐中国课标的**，目前未见成熟方案。位置是空的。

## 三、工作量估算

MVP = 小学数学「数与代数」1-6 年级（约 150 节点、300 条边）：

| 环节 | 工时 |
|---|---|
| Schema 设计 + CI 流水线 | 8h ← **已完成** |
| 课标文本获取与结构化 | 6h |
| 多 agent 生成流水线 | 16h |
| 依赖边生成 + 交叉验证 | 12h |
| 人工审核（自审） | 20h |
| MCP server + 文档 | 10h |
| **合计** | **~72h** |

全学科全学段（对标 1590 节点）：保守 600-900 小时 + 教研审核费用。
不是业余项目能完成的量级 —— 这也解释了 Marble 为什么漏了一半课标对齐。

---

## 四、覆盖缺口（做中国版时无法照搬的部分）

Marble 数据中完全没有对应节点的人教版内容：公顷/平方千米、三角形三边关系、
按边分类（等腰/等边）、烙饼沏茶类优化问题、鸡兔同笼的列表法/假设法、三视图。

反向的课标年龄错位（真实差异，非数据错误）：Marble 把四则混合运算顺序、
除数是两位数的除法、三角形内角和、平均数、鸡兔同笼标为 10-11 岁（英国 Y6），
**说明人教版在这几点上比英美课标早约一年**。

---

## 五、为什么把目标定义成"流水线"而不是"数据集"

三个目标层次，答案完全不同：

- **给自己孩子用** → 不值得。72 小时换一个单用户数据集，投入产出不成立。
- **AI Agent 开发练手** → 值得。任务形状命中要练的东西：多 agent 分工生成、
  交叉审核投票、结构化输出约束、可验证的 CI 反馈闭环、MCP 暴露。
  且有稀缺属性 —— **输出可被机器校验**，不像多数 agent 练手项目只能靠人眼看。
- **做成开源项目/产品** → 先解决两件事：(a) 找到教研员做审核背书；(b) 法律意见。
  都搞定了再投 600+ 小时，否则是在沙上盖楼。

**选择：按第 2 条做，但按第 3 条的标准设计 schema 和 provenance**，
将来想升级不用推倒重来。

按这个定位，教研审核不到位不再是致命伤，而是一个诚实标注的已知局限。
